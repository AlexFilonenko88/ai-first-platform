# Первая версия AI First Platform

## Цель

Первая версия помогает администратору подключить разработчика к проекту и подготовить локального агента к работе.

Пилот проверяет, быстрее ли разработчик получает доступ к проекту и готовое рабочее окружение.

## Пользователи и основной сценарий

В первой версии есть две роли: администратор платформы и разработчик.

Администратор создаёт проект, добавляет репозитории и инструкции, назначает разработчика и отправляет приглашение.

Разработчик принимает приглашение по корпоративной почте и входит через GitHub OAuth.

Один проект может включать несколько репозиториев. Один репозиторий может входить только в один проект.

Назначение проекта даёт разработчику доступ ко всем его репозиториям через GitHub.

## GitHub-доступ

Интеграция платформы получает доступ только к репозиториям, явно добавленным в проекты.

Платформа выдаёт участникам проекта доступ к его репозиториям и отзывает управляемые ею права.

Платформа синхронизирует права участников при добавлении или удалении репозитория в проекте.

Если GitHub требует подтверждения владельца организации, платформа показывает незавершённый шаг.

Платформа показывает обнаруженные доступы, которыми управляют вручную вне платформы.

## Инструкции и агент

Администратор хранит один Markdown-документ инструкций на проект.

Документ содержит общие правила и ссылки на файлы настройки, сборки и тестирования репозиториев.

Разработчик подключает одного агента, выбранного командой пилота по фактическому использованию.

Агент работает локально, использует GitHub-аутентификацию разработчика и готовит рабочее окружение.

Агент проверяет доступ ко всем репозиториям проекта и передаёт платформе результаты проверки.

Платформа получает только статус проекта и репозитория, категорию блокера и следующий шаг.

Агент не отправляет платформе исходный код, полные логи команд или историю диалогов.

Платформа показывает статус «готов» только после подготовки окружения и проверки всех репозиториев.

Если проверка не завершена, платформа показывает конкретный блокер и следующий шаг.

Новая редакция инструкций применяется при следующем запуске агента, но не меняет текущую сессию.

Платформа не запускает код агента и не разрешает команды от его имени.

Разработчик управляет локальными действиями по стандартным правилам подтверждения своего агента.

Агент не получает прав шире прав разработчика.

Локальный агент может использовать другие GitHub-доступы разработчика, не связанные с проектами платформы.

## Отключение сотрудника

При отключении сотрудника платформа деактивирует его учётную запись и отзывает управляемые ею GitHub-права.

Платформа показывает оставшиеся доступы, которыми управляют вручную вне платформы.

Платформа не удаляет локальные копии репозиториев или кэш агента.

Организация отвечает за очистку локальных данных в процессе отключения сотрудника.

Платформа сохраняет минимальные записи аудита по корпоративной политике хранения.

## Аудит

Журнал доступа доступен администраторам платформы.

Журнал хранит события приглашений, назначений проектов и выдачи или отзыва GitHub-доступа.

Запись содержит событие, инициатора, затронутую учётную запись, проект или репозиторий, время и результат.

Платформа фиксирует автора и время изменения инструкций, но не хранит версии для просмотра или отката.

Журнал не содержит секреты, исходный код или логи агента.

## Пилот и критерии успеха

Пилот охватывает одну команду и один проект с несколькими репозиториями.

Команда измеряет долю приглашённых разработчиков, которые достигают статуса «готов».

Команда измеряет время от приглашения до подтверждённой готовности.

Команда определяет числовые целевые значения после базового замера.

## Границы первой версии

Первая версия поддерживает только GitHub и инструкции, привязанные к проектам.

Первая версия не включает облачный запуск агентов или выполнение задач.

Первая версия не включает трекеры задач и интеграции с другими сервисами.

Первая версия не включает общий каталог навыков и инструментов.

Первая версия не включает аналитику использования или стоимости моделей.

Первая версия не включает команды и детальные роли доступа.

## Условия начала интеграции агента

До реализации команда выбирает один агент по фактическому использованию.

До пилота команда выбирает конкретную пилотную команду и проект.

Команда проверяет, что агент принимает инструкции, использует GitHub-аутентификацию разработчика и возвращает статусы готовности.
